# Writing 纯记忆审计与完整流对照

2026-11-27，北京时间 08:54。固定目标 Cute，训练流和 64 道留出题沿用首次运行时冻结的划分。本页区分 200 题串行校准与 4,800 题完整流。论文《Fast and Slow Online Learning for Agents》表 1 的 Writing 成绩为 Raw Memory 68.7%、REINFORCE++ 79.8%、RF++ + Raw 97.4%。作者在图 1 的讨论中描述了记忆在早期的快速适应。

零样本和标准纯记忆的 Cute 命中率分别为 26.5% 和 33.0%。同一题上仅纯记忆成功 33 次，仅零样本成功 20 次。在固定种子的逐题描述性比较中，精确双侧 McNemar p=0.0984。相邻四段各 50 题的纯记忆成功数为 20、14、15、17，对应零样本为 15、12、11、15。早期数据没有显示出论文描述的快速上升。在线记忆有时序依赖，单次运行的配对检验无法量化跨训练种子的不确定性。

逐条重建实际策略输入后，200/200 条与保存的输入 token 完全一致。0、1、2、3 条示例各出现 1、1、2、196 次。每次都使用了当时可用的最多 3 条，累计 593/593 次引用指向较早的 Cute、good 回答。最长输入为 2,407 token，低于 4,096 上限。对第 10、50、100、150、200 题完整解码后可见记忆标题、三组示例问答、当前写作题和生成起始标记。示例只有正文，模板把它们描述为供参考的经历，同时仍让模型自行决定当前写作风格。样例的标签来自评委，其文学判断尚无独立人工标注。

对同一批已生成的 200 段纯记忆回答，用原评委权重、相同输入 token、单条贪心解码独立复判两遍。两遍的完整风格和质量判词在 200/200 条上一致，且各自 200/200 与原记录一致。这项检查覆盖单条评委的重复性。完整流在串行前缀之后使用批量评审。[审计入口](../benchmarks/audit_writing_memory.py)

## FSOL 数值上界与留出轨迹

完整流的前 2,592 题中，FSOL 成功 1,576 次。即使余下 2,208 题全部成功，全流也至多为 3,784/4,800（78.83%），较论文 97.4% 至少低 18.57 个百分点。此轮已无法达到计划第 6.3 节的绝对数值容差。原因和完整方法排序有待对照。本地查询子集、顺序和固定目标风格与作者设置的对应关系仍未证实。

## 已部署的完整对照

- 标准纯记忆从基座和空库启动，4,800 题按同一顺序。前 320 题逐条更新记忆，随后每 16 题共用批初记忆。每 800 题对相同 64 道留出题做无记忆与当时在线记忆的四次采样。日志中每 16 题的分组编号仅表示流位置，策略权重固定。
- 纯 RL 已进入等待队列。依赖 FSOL 完整结束并获得两张可用 GPU，从原始基座开始，训练查询均不读写示例。每 50 次更新进行同题的无记忆和冻结库探针。论文配置的 KL 系数为纯 RL 0.01、FSOL 0.05。同更新数的比较可以评价两套训练方案，若要把差异归因于记忆，还需控制 KL。
- 为让 FSOL 与纯 RL 看到完全相同的示例，独立评测进程已启动，为第 200、250、300 次更新读取刚同步的权重。计划使用共同冻结的 62 条成功示例库和无记忆两种输入，按同一查询、同一采样种子各生成四次并保存风格与质量。该探针与主运行原有的在线记忆探针分别报告。前三个完整流检查点的权重已经释放，仍按实际的一次采样报告。四次采样的分析单位为查询，配对区间按 64 道题重采样。
- 在隔离进程验证了直接向推理引擎同步全部策略权重，并抽查了人为改动的一层，避免纯 RL 每步在数据盘重复写整套模型。最终纯 RL 权重拟相对冻结基座保存为可逆 BF16 差分，压缩输出上限 3 GB。完整流的结果和比较仍待作业实际结束。[完整流与对照入口](../benchmarks/time_writing_batches.py)
